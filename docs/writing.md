# 内容写作与公开规则

生产文章位于 `content/posts/`，扩展名 `.md`，可分子目录。每个文件以 `---` 包住严格 JSON 元数据，结束分隔符后是 Markdown 原文。选用 JSON 是为了避免 YAML 隐式日期/类型转换；不支持 YAML 元数据。`body` 由构建器读取正文生成，不能在元数据再声明。

以下是格式示例，只在文档中展示；请用自己的真实内容替换，不要将示例当成生产文章：

```markdown
---
{
  "schemaVersion": 1,
  "id": "my-stable-id",
  "publication": "draft",
  "title": "作者填写的真实标题"
}
---
作者填写的 Markdown 正文。
```

`schemaVersion` 固定为 1；`id` 必须稳定、非空，最多 128 个 Unicode 码点，不能含控制字符、斜杠、反斜杠或单独的 `.`/`..`。`publication` 必须明确为 `draft` 或 `published`，`title` 不能只有空白，正文允许明确为空。ID 不由文件名或标题推断。

可选字段 `summary`、`author`、`publishedAt`、`tags`、`assets` 只接受契约规定的类型。缺失与空字符串不同。`publishedAt` 若提供须为带时区的 RFC 3339 时间戳，例如格式 `2024-02-29T12:00:00+08:00`；默认按作者原值展示。摘要不会从正文自动截取；不生成匿名作者、当前时间、标签、阅读时长或封面。

`content/site.json` 可包含 `schemaVersion: 1` 与可选 `title`、`description`、`author`、`language`。缺失整个文件时生成空信息结构，不生成站点名称。站点作者不会填入缺失的文章作者。`siteId`、`sourceId`、API 地址等放在应用配置中。

静态未知字段（包括拼写错误）阻止构建，并报告源文件和字段路径。重复 ID、缺失发布状态、非法正文/资源同样失败。失败构建保留先前有效产物。

## Markdown 和图片

唯一解析链使用 `unified + remark-parse + remark-gfm`，版本和依赖锁定。支持 CommonMark 与 GFM 的段落、标题、强调、删除线、链接、代码、引用、列表/任务列表、表格、自动链接和脚注。原始 HTML 作为文字显示并给诊断，不执行脚本或模板。无法安全表达的内容报正文错误，提供转义后的原始 Markdown 入口。

本地资源路径以 `content/` 为基准，必须落在 `content/assets/` 内，例：`![作者填写的准确描述](assets/photo.png)`。远程图片须是作者提供的绝对 HTTP/HTTPS 地址。不要用页面路由作为图片基址，也不要使用 `data:` 或 `javascript:`。信息性图片必须有非空替代文本。

装饰性图片必须通过资源声明明确标识：

```json
{
  "assets": [
    { "id": "decoration", "url": "assets/decoration.png", "decorative": true, "alt": "" }
  ]
}
```

正文写 `![](asset:decoration)`。信息性资源声明使用 `decorative: false` 和非空 `alt`，正文 `![同一个准确描述](asset:资源ID)` 的描述必须与声明完全一致。每篇资源 ID 唯一；不按文件名猜测描述。资源声明本身不会自动成为封面。

相同图片出现两次会形成两个加载槽位。图片网络失败保留其他正文，允许按相同地址重试；确认静态部署已经更新后，故障资源只允许通过显式更新页面恢复。

## 发布范围

只有 `published` 文章、独立站点/目录、相应正文，以及公开正文实际引用的本地资源进入产物。草稿、草稿专属资源、未引用资源、夹具、文档和内部配置不复制到产物。符号链接经过真实路径检查，不能越出资源目录；文章文件不接受符号链接。

未来日期不改变明确的发布状态。选择/取消文章只是展示偏好，所有已发布文件仍可能被直接访问。需要权限控制的内容应由独立 API 在服务端鉴权，不能依赖前端筛选。
