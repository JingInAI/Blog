## 证据与方法

新增 `tests/boundary-lifecycle.test.ts` 十四项回归，旧实现全部失败，日志 `/tmp/blog-boundary-lifecycle-before.log`（14 项、0 通过、14 失败）。只在系统临时目录创建文件/伪项目及在可控传输中修改响应，没有将实际项目文档作为可破坏输入。

修复后十四项与六项请求生命周期共二十项通过，日志 `/tmp/blog-boundary-lifecycle-after.log`。首次类型检查发现测试 Buffer 与 DOM BodyInit 泛型不兼容，夹具改用拥有独立 ArrayBuffer 的 Uint8Array，类型复核通过；这不是生产行为问题，不计入五类逻辑缺陷。

三项补验验证：合法 UTF-8 中作者明确提供的 U+FFFD、中文、emoji 和正文内 U+FEFF 保持，网络 JSON 单个前导 BOM 兼容；已有合法目录输出在校验后仍可替换并清理备份；端点回调每次仍被调用，调用者对象不冻结。与原有来源、输入准确性和请求生命周期合计五十一项通过，日志 `/tmp/blog-boundary-lifecycle-targeted.log`。三项补验不计作修复前失败记录。

四项新增真实 Chromium 用例覆盖 HTTP Vue/React 根/子路径，往唯一 title 字段中插入非法 UTF-8 字节（不是重复 JSON 字段），确认整个正文请求 invalid-response、没有标题替代值、没有误提供普通重试、无脚本异常；撤销注入并显式重载后恢复作者标题与全文。字节注入只作用于测试页面响应。

## 行为与兼容性

本地文章、site.json、应用配置要求合法 UTF-8，解码保持 BOM 字符供原有格式规则处理；不会猜测或转码为其他编码。网络 JSON 读取完整 ArrayBuffer 后严格解码，并沿用先前 Response.text() 对单个前导 UTF-8 BOM 的兼容，字符串内部字符不删除。字面 U+FFFD 的合法编码仍允许，拒绝依据是字节序列合法性，不是字符值。

注入 FetchPort 应返回可读取原始字节的 Response；迟到传输桩改为 arrayBuffer()，真实 HTTP 的正文取消、超时和未读流释放继续验证。超时覆盖读取，不保证强制终止忽略取消的自定义实现。

既有来源配置在创建时固定，切换 sourceId、构建版本、端点或资源基址须创建新工厂并调用 changeSource。端点和策略回调保留显式函数引用，回调自己捕获的外部状态不被自动复制或冻结。调用者的原配置仍可用于创建另一来源；不是冻结整个调用者对象。

输出仍可为不存在的目录或合法已有目录，正常原子更新继续使用暂存/备份。已有文件、特殊节点等非目录输出拒绝；源/输出重叠继续先报 source-output-overlap。路径校验不承诺抵御外部进程在检查与提交之间主动修改文件系统。
