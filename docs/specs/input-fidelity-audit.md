## 证据与方法

新增 `tests/input-fidelity.test.ts`。最初十六项在旧实现全部失败；再补充两项返回对象引用隔离回归，十八项旧实现全部失败，最终修复前日志 `/tmp/blog-input-fidelity-before.log`（18 项、0 通过、18 失败）。修复后连同请求生命周期、分享和主题契约共 34 项通过，日志 `/tmp/blog-input-fidelity-after.log`。

另有两项补验：共享 JSON 扫描保持原生语法、合法字符串/转义、不同对象同名键、嵌套数组及 12000 层数组输入，拒绝同对象重复键；只读验证器可检查合法嵌套选项，输出保留原值且不冻结作者输入。二十项定向测试全部通过，日志 `/tmp/blog-input-fidelity-targeted.log`。两项补验没有修复前失败记录。

新增四项真实 Chromium 场景覆盖 HTTP Vue/React 根/子路径，在原始 API 正文响应插入重复 title，验证 invalid-response、没有展示任何标题替代值、没有误提供普通内容重试、无脚本错误；撤销注入并显式重载后恢复作者标题与全文。响应注入不改测试服务器文件或生产内容。

原始 JSON 使用原生 JSON.parse 检查语法，再以字符串词法边界进行迭代扫描；每个对象持有独立键集合，不把字符串里的引号/括号当作结构，也不把不同对象同名字段当作重复。键由 JSON 解码后精确比较，不额外做大小写或 Unicode 归一化。此规则有意比原生 JSON.parse 严格，合法无歧义内容保持值与顺序。

网络请求改用 Response.text() 后统一解析，取消和超时仍覆盖完整正文读取；原有真实 HTTP 连接释放与迟到传输回归保留，并将迟到桩改为 text()。先前稀疏 API 注入回归改为发送实际序列化数组，其中 null 条目必须失败；标签、资源、请求 ID 和框架注册的稀疏位置校验仍保留。

附加验证器只读取冻结快照；有写操作的扩展应改用显式迁移，不允许隐式转换通过校验。正常外部 dispatch 仍即时执行，只有通知中的事件排队时保存输入快照。现有内置主题、生产内容格式、Vue/React 支持及未来框架端口保持。

最终完整本地检查退出码 0：136 项逻辑/构建、类型与边界、双生产构建及 61 项 Chromium 全部通过，无失败或重试。[本机验收 JSON](../../.generated/local-smoke/input-fidelity-results.json) 核对二十项新增逻辑、四项新增 HTTP 场景、25 个固定端口关闭与实例目录清空；公开内容及 CSS 哈希与前轮一致。JavaScript 和 index.html 引用随修复改变，不能声称全部产物哈希不变。十二份 Markdown 及本地链接由本轮审计复核，生产内容未增加作者事实。
