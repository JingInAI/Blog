# 准确性、鲁棒性与可靠性审查

审查日期：2026-10-05。修订：implementation-13。范围是当前本地实现，依据 [设计文档](design.md)、实际源代码、可复现失败及本地验收。执行证据见 [执行记录](../plans/execution.md)。本轮没有查询 GitHub、推送或线上发布，也没有接入真实后端。

## 方法与范围

逐项审查内容契约、静态内容构建、HTTP 适配器、取消/超时/响应正文生命周期、控制器初始化与来源切换、配置持久化、分享/路由协议、主题扩展、唯一 Markdown 转换链、Vue/React 资源与表单生命周期、构建隔离和退出清理。以实际失败确认问题，再修复并运行完整检查。没有将类型检查或浏览器功能通过当作连接释放、产物保真或测试清理已经完成。

## 兼容性和验证边界

个人存储键现在是 `blog:<编码siteId>:<编码sourceId>:display:v1`，不含框架 ID。当前生产身份 blog/public-content 及常见 ASCII 身份的键不变。旧版本中包含冒号、百分号、中文等需要编码的身份会改用新键；旧记录保留，但不自动迁移含歧义的旧命名空间，需重新选择或显式保存个人配置。避免为兼容碰撞而再次自动读取错误记录。

API 基址现在拒绝 query/fragment；既有集成若依赖这种写法，需要把认证交给 requestPolicy，或通过 endpoints 声明具体请求参数，不将凭据放入公开配置。basePath 的非 ASCII 字符和空格须使用 UTF-8 百分号编码；编码后的路径分隔符、控制字符仍拒绝。作者空链接保留浏览器的当前文档链接语义，不改写为推测的外部或附件地址。

本轮已修复所有已复现的问题。代码审查与受控测试不能证明没有未知缺陷；真实 API 的授权、CORS、服务可用性以及 GitHub Pages 发布仍需对应外部环境验收。本轮未查询外部依赖漏洞数据库；SSR/SEO、真实线上认证和强制 SIGKILL 后的清理不在本轮验证结论内。生产内容仍为空，不添加测试文章或猜测作者信息。
