## 测试方法与兼容范围

新增 `tests/version-lifecycle.test.ts`。最初十四项回归在旧实现全部失败，日志 `/tmp/blog-version-lifecycle-before.log`；修复后十四项全部通过，日志 `/tmp/blog-version-lifecycle-after.log`。再添加两项补验：根/子路径、合法编码版本身份及自定义文件名能初始化；错配探测指针不能确认更新，修正后的指针可重新探测并确认。相关来源、控制器、完整性与新增回归合计 54 项通过，日志 `/tmp/blog-version-lifecycle-targeted.log`。两项补验没有修复前失败记录，不能与十四项复现合并声称全部先失败。

双框架静态浏览器新增四项场景，分别覆盖 Vue/React 的根路径与 /Blog/。每项注入五种跨版本指针/清单映射，检查启动报 invalid-response、没有读取站点/目录/正文/图片、没有误显示普通重试或已确认更新。注入只作用于测试页面的响应，不改作者内容与生成的静态文件。

正式构建原已采用版本目录，不改变生产内容格式或作者字段；旧测试中手工编写的无版本目录地址已调整为实际格式。自定义静态生产者须采用同样目录约束。合法版本不需要强制为哈希，自定义 ID 编码后可用；实际构建器继续使用 SHA-256。目录验证不等于重新计算每个远程响应的文件摘要，不承诺抵御有权修改同版本文件的服务器。

通知中的状态操作延后到微任务，常规外部调用保持即时语义；destroy 立即生效。已有进行中请求仍按 AbortSignal 取消和加载代号处理，不能强制结束忽略取消的自定义来源。此次修复没有新增自动重试、换源、事实补全或缓存回退。完整验收和本机审计结果记于执行记录，不把受控本地测试称为真实线上验证。
